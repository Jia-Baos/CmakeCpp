在这个例子中，用户之间的消息交互并没有直接发生，而是通过 ChatRoom 中介者进行的。每当一个用户发送消息时，消息会被 ChatRoom 中介者转发给其他所有用户，从而避免了用户之间直接的依赖关系。

## 优点

- 解耦：中介者模式将各个同事类之间的交互转化为对中介者的交互，使得同事类之间不再直接依赖，降低了类之间的耦合度。

- 集中控制：所有的交互逻辑集中在中介者中，方便管理和修改。

- 扩展性强：如果需要添加新的功能或新的同事类，只需修改中介者，其他类无需修改。

## 缺点

- 复杂性增加：当中介者的职责变得复杂时，可能会导致中介者类变得庞大且难以管理。

- 不易理解：对于较简单的系统，使用中介者模式可能显得过于复杂，容易让代码结构变得不直观。

## 适用场景

中介者模式适用于以下场景：

- 多个对象之间存在复杂的交互关系，直接的交互关系难以维护时。

- 希望通过集中管理对象之间的交互来简化系统的结构。

- 各个对象之间的通信较为复杂，采用中介者可以减少对象之间的耦合度。
