## 代码解释

- Command 接口：定义了 execute() 方法，所有的具体命令都需要实现这个接口。

- Light 类：作为接收者类，负责具体的操作（开灯和关灯）。

- TurnOnLightCommand 和 TurnOffLightCommand：这些是具体的命令类，封装了对 Light 类的操作。

- RemoteControl 类：调用者类，它使用命令对象来发起请求，调用 execute() 方法。

## 优点

- 解耦：命令模式将请求的发起者和执行者解耦，发送者无需知道具体的接收者。

- 易于扩展：可以轻松添加新的命令类，而无需修改现有代码。

- 支持撤销操作：可以通过保存历史命令的对象，来实现命令的撤销。

- 参数化：可以通过命令参数来执行不同的操作。

## 缺点

- 命令类增多：如果有很多不同的操作，可能会创建大量的命令类，增加系统的复杂性。

- 代码执行路径不直观：由于请求是通过命令对象传递的，可能使得代码的执行路径不如直接调用那样清晰。

## 应用场景

命令模式适用于以下情况：

- 当需要将请求调用者和请求接收者解耦时。
- 当你希望支持撤销操作时（例如在编辑器中撤销或重做操作）。
- 当你需要将多个操作封装成一个操作来进行队列处理时。
