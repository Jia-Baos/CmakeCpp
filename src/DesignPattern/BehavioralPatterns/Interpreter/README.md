## 代码解释
- 上下文（Context）：Context 类可以存储一些全局信息，如变量值等，但在这个例子中我们没有用到变量，仅用于展示上下文的概念。

- 抽象表达式（Expression）：Expression 类是一个接口，所有的具体表达式类都继承自它，并实现 interpret() 方法来解释表达式。

- 终结符表达式（Number）：Number 类表示一个具体的数字，它直接返回自身的值。

- 非终结符表达式（AddExpression 和 SubtractExpression）：这些类代表加法和减法运算，它们通过递归地调用 interpret() 方法来计算左右操作数的值，并返回运算结果。

- 表达式解析器（ExpressionParser）：ExpressionParser 类负责解析字符串表达式，并生成一个表达式树。它使用简单的递归方式来解析加法和减法运算。

- 客户端（Client）：客户端通过 ExpressionParser::parse() 解析表达式，然后通过 interpret() 方法来获取结果。

## 优点

- 易于扩展：可以非常容易地添加新的操作符（如乘法、除法）或表达式类型，只需定义新的 Expression 子类即可。

- 支持递归解释：由于表达式是树形结构，可以递归地解释复杂的表达式。

- 文法的清晰表达：通过表达式树，能够清晰地表示文法规则。

## 缺点

- 复杂性：对于非常简单的表达式，使用解释器模式可能会显得过于复杂。

- 性能问题：递归结构可能导致性能问题，尤其是在解释复杂或大规模的输入时。

## 应用场景

解释器模式适用于以下场景：

- 需要设计一个小型语言或表达式求值引擎时。

- 需要处理复杂的语法规则或命令解析时。

- 需要执行和评估数学公式、配置文件、查询语言等。
