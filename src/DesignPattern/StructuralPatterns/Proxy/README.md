## 解释：

- File：定义了目标对象和代理对象共同的接口。这个接口包括 read() 方法，所有的文件操作都通过它来进行。

- RealFile：是实际的文件对象，实现了 File 接口，模拟了一个文件的加载和读取。它只有在需要时才加载文件。

- ProxyFile：是代理对象，也实现了 File 接口。在调用 read() 方法时，代理会检查是否已经加载过 RealFile 对象，如果没有，则延迟加载文件。

## 代理模式的优点：

- 延迟加载：通过代理模式可以推迟实际对象的创建，避免了不必要的资源消耗。

- 访问控制：可以在代理对象中添加权限控制或其他附加逻辑，保护真实对象。

- 减少耦合：客户端代码只与代理对象交互，而不直接与真实对象交互，有助于解耦。

- 增强功能：代理模式允许我们在不修改目标对象的情况下增加额外的功能（如日志、缓存、计数等）。

## 代理模式的缺点：

- 复杂性增加：代理模式会增加系统的复杂性，因为需要引入额外的代理对象。

- 性能开销：虽然代理模式可以优化资源的使用，但代理本身会增加方法调用的开销，特别是在频繁访问的场景下。

## 使用场景：

- 虚拟代理：当需要延迟加载资源（如大文件、图片等），并且资源的创建开销较大时，可以使用虚拟代理。

- 远程代理：当需要通过网络访问远程对象时，可以使用代理模式，代理对象负责与远程对象通信，简化客户端的操作。

- 保护代理：用于控制对某些对象的访问，可以根据权限来决定是否允许操作目标对象。

- 智能代理：当需要附加功能（如引用计数、线程安全等）时，可以使用智能代理。
