## 解释：

- ChessPiece 是享元接口，它定义了 display 方法来展示棋子的位置。

- Queen 和 Knight 是具体享元类，它们实现了 ChessPiece 接口，并提供了棋子的类型（这些类型是共享的）。

- ChessPieceFactory 是享元工厂类，它负责管理享元对象的创建和共享。每次请求一个棋子时，工厂会返回已有的实例，而不是重新创建。

- ChessBoard 是客户端类，它使用享元工厂来获取共享的棋子对象，并在棋盘上显示它们。

## 享元模式的优点：

- 节省内存：通过共享相同类型的对象，避免了重复创建对象，节省了大量内存。

- 提高性能：当系统中有大量相似对象时，享元模式可以显著减少对象的创建和销毁，提高程序性能。

- 简化对象管理：享元工厂负责对象的管理，确保对象的共享，客户端代码变得简单。

## 享元模式的缺点：

- 外部状态管理复杂：享元模式要求将对象的状态分为内部状态和外部状态，外部状态需要由客户端管理，这可能增加复杂性。

- 共享对象的细粒度控制：如果享元对象的粒度控制不当，可能会导致不必要的共享，增加代码的复杂度。

## 使用场景：

- 当系统中有大量相似对象且这些对象的内部状态（数据）相同，可以使用享元模式来减少内存使用。

- 例如，大量的字符对象、图形对象等。

- 在游戏开发中，尤其是棋盘类游戏中，不同位置的棋子可能是相同的类型，通过享元模式可以优化内存使用。
