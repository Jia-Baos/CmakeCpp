## 代码说明：

- Component 是所有对象的基类，定义了一个纯虚函数 operation。

- Leaf 是叶子节点的类，提供具体的 operation 实现。

- Composite 是复合节点的类，内部包含子组件（可以是叶子节点或其他复合节点）。它也实现了 operation 方法，并递归地调用每个子组件的 operation 方法。

- 客户端（main 函数）创建了叶子节点和复合节点，并通过复合节点来调用操作。

## 组合模式的优势：

- 透明性：客户端通过统一的接口访问所有对象，既可以访问叶子节点，也可以访问复合节点。

- 简化代码：通过递归地将叶子节点和复合节点结合，可以减少冗余代码。

- 灵活性：可以方便地添加新的节点类型，扩展系统。

## 组合模式的缺点：

- 设计复杂性：如果对象结构较简单，使用组合模式可能会增加不必要的复杂性。

- 效率问题：递归可能导致性能问题，尤其是在树形结构很大的时候。
